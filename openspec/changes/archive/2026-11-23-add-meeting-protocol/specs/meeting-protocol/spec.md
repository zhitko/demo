# Spec Delta

## Purpose

Строит протокол встречи из готовой текстовой расшифровки: решения, задачи с ответственными и открытые вопросы, чтобы руководитель показал результат за минуту.

## ADDED Requirements

### Requirement: Одна страница без входа
Система SHALL открывать один экран на русском языке, с которого руководитель начинает сценарий, без входа в учётную запись.

#### Scenario: Страница открыта
- **WHEN** руководитель открыл страницу
- **THEN** на ней можно выбрать файл расшифровки и видна кнопка «Сделать протокол»

### Requirement: Загрузка готовой расшифровки
Система SHALL принимать один текстовый файл UTF-8 с расширением `.txt` как готовую расшифровку и MUST NOT запускать распознавание речи.

#### Scenario: Выбран текстовый файл
- **WHEN** пользователь выбрал текстовый файл с расшифровкой
- **THEN** система принимает текст файла как исходные данные протокола и не запускает распознавание речи

### Requirement: Протокол только по кнопке
Система SHALL строить протокол только после нажатия кнопки «Сделать протокол» по уже выбранной расшифровке.

#### Scenario: Нажата кнопка
- **WHEN** файл с расшифровкой загружен и пользователь нажал «Сделать протокол»
- **THEN** система строит протокол по этой расшифровке

### Requirement: Три блока результата
Система SHALL одновременно показать блоки «Решения», «Задачи» и «Открытые вопросы». У каждой задачи SHALL быть указан ответственный.

#### Scenario: Протокол построен
- **WHEN** протокол построен
- **THEN** на экране одновременно видны «Решения», «Задачи» с ответственным у каждой задачи и «Открытые вопросы»

### Requirement: Учебные блоки не смешиваются
Для учебной расшифровки `samples/transcript-demo.txt` система SHALL разложить эталон по блокам: три решения, две задачи и один открытый вопрос.

#### Scenario: Три решения совпадают с оригиналом
- **WHEN** протокол построен по учебной расшифровке
- **THEN** в «Решениях» ровно эти три формулировки: «Команда сдаёт одну спецификацию и один прототип.», «На защите команда показывает один сценарий за три минуты.», «В материалах только учебные данные, без персональных сведений.»

#### Scenario: Задачи и открытый вопрос
- **WHEN** протокол построен по той же учебной расшифровке
- **THEN** в «Задачах» ответственные «Участник А» и «Участник Б», а в «Открытых вопросах» вопрос «До скольких страниц принимать файл расшифровки?»

### Requirement: Скачивание того же протокола
Система SHALL отдавать текущий протокол текстовым файлом UTF-8, и содержание файла SHALL совпадать с тремя блоками на экране.

#### Scenario: Файл совпадает с экраном
- **WHEN** протокол уже виден на экране и пользователь скачивает результат
- **THEN** в файле те же решения, задачи с ответственными и открытые вопросы, что на экране

### Requirement: Протокол не позже чем через минуту
Система SHALL показать протокол не позднее чем через одну минуту после нажатия «Сделать протокол».

#### Scenario: Укладываемся в минуту
- **WHEN** расшифровка загружена и нажата кнопка «Сделать протокол»
- **THEN** не позднее чем через одну минуту на экране показан протокол

### Requirement: Один текущий протокол
Система SHALL хранить в сеансе только текущий протокол. Новая успешная загрузка и повторное нажатие «Сделать протокол» SHALL заменить протокол на экране. Истории встреч SHALL NOT быть.

#### Scenario: Другой файл заменяет протокол
- **WHEN** пользователь загрузил другой текстовый файл и снова нажал «Сделать протокол»
- **THEN** на экране протокол по новому файлу, а предыдущий протокол нигде не сохраняется

### Requirement: Эталон без сети
Когда живая модель выключена или недоступна, система SHALL для учебной расшифровки показать заранее названный эталонный протокол без обращения к сети.

#### Scenario: Модель выключена
- **WHEN** загружена учебная расшифровка, модель выключена и нажата «Сделать протокол»
- **THEN** на экране эталонный протокол, и вызов внешней модели не требуется
