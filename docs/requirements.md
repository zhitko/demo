# Спецификация прототипа: протокол из расшифровки встречи

Источник: лекция Николая «Прототип — это вопрос», хакатон Invento Labs × ФРФиКТ БГУ. Этот файл разворачивает паспорт прототипа с его слайда «Паспорт прототипа» в текст для агента.

Формулировки паспорта, сценария, границ и критерия взяты из презентации. Пометкой **(дополнено для демо)** отмечено только то, чего в презентации нет, но без чего нельзя собрать и проверить рабочий прототип. Открытые места из презентации (пометки TBD) не заполняются выдуманными цифрами: они вынесены в раздел «Открытые вопросы».

---

## Паспорт прототипа

Шесть полей — как на слайде «Паспорт прототипа». Где на соседних слайдах формулировка полнее, она приведена рядом, в квадратных скобках.

1. **Для кого и какая боль.** Руководитель проекта после созвона: на протокол уходит время, договорённости теряются.  
   [Полнее, слайд «Кто, какая боль и что проверяем»: кто — руководитель проекта после часового созвона; боль — ещё TBD минут уходит на протокол, часть договорённостей теряется; сейчас — пишет по памяти или не пишет вовсе.]

2. **Гипотеза: что проверяем.** Протокол из расшифровки за минуту; участник признаёт его верным без существенных правок.  
   [Полнее: «Мы считаем, что руководитель получит протокол из расшифровки встречи за минуту. Мы правы, если участник встречи признает решения и задачи в протоколе верными без существенных правок».]

3. **Сценарий показа, 3–5 шагов.** Открыл · загрузил файл · нажал «Сделать протокол» · увидел три блока · скачал.  
   [Полнее, слайд «Один сценарий от начала до конца»: 1) открыл страницу; 2) загрузил файл с расшифровкой; 3) нажал «Сделать протокол»; 4) увидел решения, задачи с ответственными и открытые вопросы; 5) скачал результат.]

4. **Входит / не входит.** Файл, три блока, скачивание / речь, логин, история, календарь, правка, мобильная версия.  
   [Полный разбор десяти возможностей — в разделе «Границы»; он взят со слайда «Входит, не входит, допускаем».]

5. **Допущения.** Расшифровка готова, язык русский, один пользователь, учебные данные.  
   [Полнее: расшифровка уже готова; язык — русский; один файл до TBD страниц; один пользователь; учебные данные без персональных.]

6. **Критерий: что покажем на защите.** Три решения из протокола совпадают с оригиналом.  
   [Полнее, слайд «Как поймём, что получилось»: загружаем расшифровку, которую сервис не видел; через 1:00 на экране протокол; жюри сверяет три решения с оригиналом — совпадают.]

## Цель и пользователи

Прототип отвечает на вопрос: «Так ли это должно работать для человека?» Его показывают заказчику и пользователям. Результат хакатона, по формулировке Николая, — «прототип одного сценария. Он показывает, что концепт живой».

**Пользователь.** Руководитель проекта после часового созвона. Сейчас он пишет протокол по памяти или не пишет вовсе; из-за этого часть договорённостей теряется.

**Кому показывают результат.** Участник той же встречи (на защите хакатона это роль жюри): он сверяет протокол с оригиналом расшифровки.

Сырая идея на лекции звучала шире: «ИИ-ассистент для встреч» — записывает созвоны, пишет протоколы, ставит задачи в трекер, напоминает о сроках, считает, кто сколько говорил, есть мобильное приложение. В прототип из этого берётся только узкий сценарий «протокол из готовой расшифровки».

## Границы

Список «не входит» важнее списка «входит». Агенту нужно прямо сказать, чего не делать, иначе он может добавить это сам.

### Входит

Со слайда «Входит, не входит, допускаем» (карточки без вычёркивания):

- загрузка текстового файла;
- три блока результата: решения, задачи с ответственными, открытые вопросы;
- скачивание.

### Не входит

Вычеркнуто на том же слайде:

- распознавание речи (самое эффектное убрали: гипотеза не про него);
- вход по логину;
- история встреч;
- связь с календарём и трекером;
- правка протокола в интерфейсе;
- мобильная версия;
- напоминания о сроках.

В краткой строке паспорта «напоминания о сроках» не повторены, а «связь с календарём и трекером» сжата до «календарь». Для спецификации действует полный список слайда с упражнением.

Дополнительно, как общий принцип прототипа на лекции (слайд «Хакатон — один оборот цикла»), в прототипе сознательно нет: защиты данных, обработки ошибок, реальных данных, нагрузки, поддержки.

### Допущения

- Расшифровка уже готова.
- Язык — русский.
- Один файл до TBD страниц (число в презентации не зафиксировано, см. «Открытые вопросы»).
- Один пользователь.
- Учебные данные без персональных.

Допущение не обман, если оно названо. Заглушка, о которой сказали заранее, — проектное решение; заглушка, о которой промолчали, — провал на защите.

**(дополнено для демо)** Формат расшифровки — текстовый файл в кодировке UTF-8 с расширением `.txt`. В презентации сказано только «текстовый файл» и «файл с расшифровкой».

**(дополнено для демо)** Скачиваемый результат — текстовый файл UTF-8 с тем же протоколом, что на экране: три блока «Решения», «Задачи» и «Открытые вопросы». В презентации сказано только «скачал результат», формат не назван.

**(дополнено для демо)** Интерфейс прототипа — на русском, одна страница в браузере, без входа в учётную запись.

**(дополнено для демо)** Генерация протокола в этом прототипе может опираться на заранее названную заглушку: для учебной расшифровки из приложения к этой спецификации сервис показывает эталонный протокол, если живая модель недоступна или её ответ нельзя гарантировать за минуту. Это сознательная заглушка, о которой сказано заранее. Наличие конкретной модели, ключей и внешнего API в паспорт не входит.

**(дополнено для демо)** В одном сеансе действует один текущий файл: новая успешная загрузка и повторное нажатие «Сделать протокол» заменяют протокол на экране. Истории встреч нет.

## Функциональные требования

У каждого требования есть способ проверить его сценарием «когда… тогда…». Слова вроде «удобно», «умно», «быстро» в требования не входят: в презентации они приведены как плохой критерий.

### FR-01. Одна страница

Пользователь открывает одну страницу сервиса и может начать сценарий показа.

- **SC-01.** Когда руководитель открыл страницу, тогда на ней можно загрузить файл с расшифровкой и видна кнопка «Сделать протокол». **(дополнено для демо:** состав элементов до загрузки в презентации не расписан, только шаг «открыл страницу».)

### FR-02. Загрузка текстового файла с расшифровкой

Пользователь загружает один текстовый файл с уже готовой расшифровкой. Распознавание речи система не выполняет.

- **SC-02.** Когда пользователь выбрал текстовый файл с расшифровкой, тогда сервис принимает этот файл как исходные данные для протокола и не запускает распознавание речи.

### FR-03. Кнопка «Сделать протокол»

Протокол строится только по нажатию кнопки с подписью «Сделать протокол».

- **SC-03.** Когда файл с расшифровкой загружен и пользователь нажал «Сделать протокол», тогда сервис строит протокол по этой расшифровке.

### FR-04. Три блока результата

На экране появляется протокол из трёх блоков: решения; задачи с ответственными; открытые вопросы.

- **SC-04.** Когда протокол построен, тогда на экране одновременно видны три блока: «Решения», «Задачи» (у каждой задачи указан ответственный) и «Открытые вопросы».
- **SC-05.** Когда в учебной расшифровке есть решения, задачи и открытые вопросы, тогда они попадают в соответствующие блоки и не смешиваются. **(дополнено для демо:** правило разнесения по блокам в презентации задано названиями блоков, но без формального разбора текста.)

### FR-05. Скачивание результата

Пользователь скачивает результат показанного протокола.

- **SC-06.** Когда протокол уже виден на экране, тогда пользователь может скачать его как текстовый файл, и содержание файла совпадает с тремя блоками на экране. **(формат файла дополнен для демо, см. допущения.)**

### FR-06. Критерий защиты: минута и три решения

Критерий пишут до начала работы. Его можно показать на экране и с ним нельзя спорить.

- **SC-07.** Когда загружена расшифровка, которую сервис ещё не видел, и нажата кнопка «Сделать протокол», тогда не позднее чем через одну минуту на экране показан протокол.
- **SC-08.** Когда протокол построен по учебной расшифровке с известным оригиналом, тогда в блоке «Решения» есть три решения, и они совпадают с оригиналом.
- **SC-09.** Когда участник встречи читает блоки «Решения» и «Задачи», тогда он признаёт их верными без существенных правок.

Учебная расшифровка и эталон трёх решений, задач и открытых вопросов, по которым проводится эта проверка, приведены в приложении. **(самого текста расшифровки и эталона в презентации нет — дополнено для демо.)**

## Данные

- На вход подаётся один текстовый файл с расшифровкой на русском языке. Персональных данных, паролей и ключей в файле нет: спецификация и учебные материалы уходят в публичный репозиторий.
- На экране и в скачиваемом файле хранится только текущий протокол из трёх блоков. Учётных записей, журнала встреч и связи с календарём или трекером нет.
- **(дополнено для демо)** Для проверки используется учебная расшифровка из приложения и парный эталон протокола. Это не реальные данные созвона.

---

## Как проверить

Проверка совпадает со сценарием показа и с критерием защиты.

1. Открыть страницу прототипа.
2. Загрузить учебную расшифровку из приложения (сервис не должен опираться на то, что уже «видел» её раньше в этом показе).
3. Нажать «Сделать протокол».
4. Засечь время: протокол из трёх блоков должен появиться на экране не позже чем через 1:00.
5. Сверить три решения на экране с эталоном в приложении — формулировки совпадают.
6. Сверить задачи с ответственными и открытые вопросы с тем же эталоном; участник признаёт их верными без существенных правок.
7. Скачать результат и убедиться, что в файле те же три блока, что на экране.

Не проверяем (и не требуем) вход, историю, мобильную вёрстку, правку протокола, календарь, трекер, напоминания, распознавание речи, защиту данных, нагрузку и работу на реальных записях встреч.

## Открытые вопросы

Чего нет в паспорте и в словах лекции, то агент не додумывает. Такие места записаны здесь и ждут ответа человека.

1. Сколько минут сейчас уходит на протокол вручную? На слайде «Кто, какая боль и что проверяем» стоит TBD. На сборку и проверку прототипа это число не влияет.
2. До скольких страниц принимать один файл? На слайде «Входит, не входит, допускаем» стоит TBD. Пока лимит страниц не задаём.
3. Что делать, если файл пустой, не текстовый или в расшифровке нет ни одного решения? Обработка ошибок в прототипе сознательно не входит; поведение не задано.
4. Нужна ли в интерфейсе сама расшифровка рядом с протоколом, чтобы жюри сверяло три решения с оригиналом, не открывая файл отдельно? В сценарии показа этого шага нет.

## Приложение. Учебная расшифровка и эталон

**(весь раздел дополнен для демо)** В презентации есть критерий «жюри сверяет три решения с оригиналом», но самой расшифровки и эталона нет. Ниже — вымышленный учебный текст без персональных данных, паролей и ключей. Имена людей не используются, только роли «Ведущий», «Участник А», «Участник Б». Это не запись реальной встречи.

### Учебная расшифровка

Имя файла: `transcript-demo.txt`

```text
Учебная расшифровка встречи
Тема: подготовка защиты учебных прототипов
Участники: Ведущий, Участник А, Участник Б

Ведущий: Нам нужно зафиксировать, как команды сдают работы на защиту.
Участник А: Предлагаю простое правило: каждая команда сдаёт одну спецификацию и один прототип.
Ведущий: Принимаем решение: команда сдаёт одну спецификацию и один прототип.
Участник Б: На защите лучше не разбрасываться. Команда показывает один сценарий за три минуты.
Ведущий: Принимаем решение: на защите команда показывает один сценарий за три минуты.
Участник А: В материалах не должно быть настоящих персональных данных.
Ведущий: Принимаем решение: в материалах только учебные данные, без персональных сведений.
Ведущий: Ещё задачи. Участник А готовит шаблон паспорта прототипа к пятнице. Участник Б собирает учебную расшифровку для показа.
Участник Б: Открытый вопрос: мы так и не зафиксировали, до скольких страниц принимать файл расшифровки.
Ведущий: Верно, этот вопрос оставляем открытым.
```

### Эталон протокола

**Решения**

1. Команда сдаёт одну спецификацию и один прототип.
2. На защите команда показывает один сценарий за три минуты.
3. В материалах только учебные данные, без персональных сведений.

**Задачи**

1. Подготовить шаблон паспорта прототипа к пятнице — ответственный: Участник А.
2. Собрать учебную расшифровку для показа — ответственный: Участник Б.

**Открытые вопросы**

1. До скольких страниц принимать файл расшифровки?
