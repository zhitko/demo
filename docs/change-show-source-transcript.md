# Требование: сверить три решения с оригиналом

Дополнение к `docs/requirements.md`. Базовый сценарий не меняется: загрузка файла, кнопка «Сделать протокол», три блока, скачивание.

## Зачем

После созвона участник встречи сверяет три решения в протоколе с оригиналом расшифровки. Сейчас для этого нужно открывать файл отдельно. На том же экране, где протокол, должен быть виден исходный текст, а под каждым решением — строка, из которой оно взято.

## Сценарий

1. Протокол уже построен по загруженной расшифровке.
2. Участник видит три блока и рядом текст этой расшифровки.
3. Под каждым решением читает цитату и сверяет формулировку с оригиналом.
4. Если загружен другой файл и снова нажата «Сделать протокол», на экране и протокол, и текст источника от нового файла.

## Как проверить

- **Когда** протокол построен, **тогда** текст загруженной расшифровки виден рядом с блоками «Решения», «Задачи» и «Открытые вопросы».
- **Когда** протокол построен по учебной расшифровке, **тогда** под каждым из трёх решений стоит его строка:
  - «Ведущий: Принимаем решение: команда сдаёт одну спецификацию и один прототип.»
  - «Ведущий: Принимаем решение: на защите команда показывает один сценарий за три минуты.»
  - «Ведущий: Принимаем решение: в материалах только учебные данные, без персональных сведений.»
- **Когда** пользователь выбрал другой текстовый файл и снова нажал «Сделать протокол», **тогда** и три блока, и показанный текст заменены этим файлом. До повторного нажатия на экране остаются предыдущий протокол и предыдущий текст.

## Не входит

Правка протокола, вход, история встреч.

## Промпт для агента

Скопируйте в чат Cursor как есть. Агент только готовит изменение, код не пишет.

```text
Прочитай docs/change-show-source-transcript.md и предложи изменение OpenSpec с именем show-source-transcript: proposal, сценарии «когда… тогда…», design и tasks.md. Код не меняй и задачи не реализуй. Остановись, когда tasks.md можно прочитать вслух.
```
