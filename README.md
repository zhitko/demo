# Протокол из расшифровки

Учебный прототип для лекции «От спецификации до прототипа». Одна страница: руководитель загружает готовую расшифровку, нажимает «Сделать протокол», видит три блока и скачивает результат.

Речи, входа, истории, календаря, трекера и правки протокола здесь нет. Это сознательная граница прототипа, а не недоделка.

## Стек

Vite, React и TypeScript. Сборки хватает для показа без сервера: протокол считает заглушка в браузере. Сеть для сценария показа не нужна.

## Как запустить

Нужен Node.js 22.20 или новее (так требует OpenSpec CLI, он же стоит в зависимостях).

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`).

Проверка эталона и спецификаций:

```bash
npm test
npx openspec validate --all --strict
```

## Сценарий показа

1. Откройте страницу.
2. Загрузите учебный файл `samples/transcript-demo.txt`. Это вымышленная расшифровка: роли «Ведущий», «Участник А», «Участник Б», без имён людей.
3. Нажмите «Сделать протокол».
4. На экране три блока: «Решения», «Задачи» (у каждой указан ответственный) и «Открытые вопросы». Три решения совпадают с эталоном в `docs/requirements.md`.
5. Нажмите «Скачать протокол». Файл `protokol.txt` — тот же текст трёх блоков, UTF-8.

Повторная загрузка другого `.txt` и новое нажатие заменяют протокол. Истории нет.

Для учебной расшифровки заглушка возвращает эталон и не ходит в сеть. Другой файл разбирается по меткам «Принимаем решение:», «Участник … готовит/собирает …» и «Открытый вопрос:». Так повторный показ не оставляет на экране предыдущий протокол. Это не общий разбор произвольной речи.

Живая модель выключена. Чтобы включить её, скопируйте `.env.example` в `.env` и задайте `VITE_USE_LLM=true` и `VITE_LLM_URL`. Если вызов не удался, страница снова берёт заглушку. На лекции флаг не включайте.

## OpenSpec

Спецификация паспорта лежит в `docs/requirements.md` как есть. Поведение прототипа записано в `openspec/specs/meeting-protocol/spec.md`. Изменение, которым этот прототип собран, уже применено и лежит в `openspec/changes/archive/`.

`openspec init` для Cursor (OpenSpec 2.1) кладёт навыки в `.agents/skills/`. Файлы `AGENTS.md` и правила `.cursor` текущая версия CLI не создаёт: Cursor читает навыки из `.agents/skills/`.

Следующее изменение на лекции — `show-source-transcript` (показать расшифровку рядом с протоколом и цитату под каждым решением). В этой ветке его нет: его создают вживую.
